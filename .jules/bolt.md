## 2024-05-30 - Prometheus metrics collection O(N^2) loop optimization
**Learning:** In the `admin_get_metrics` function of `telemetry_server/app.py`, calling `collector.collect()` inside the loop for every single metric fetched causes an O(N^2) performance degradation. This is exacerbated when we have multiple metrics and labels, as `collector.collect()` reconstructs metrics across the entire registry every time.
**Action:** Replaced repeated `.collect()` calls inside `get_metric_value` with a single pre-collection pass at the start of the function, caching the results into a dictionary keyed by `metric.name`. This reduces metric retrieval to O(1) dictionary lookups while preserving functional correctness. This also resolves an issue noted in memory about caching by `sample.name` instead of `metric.name` which breaks existing logic.
